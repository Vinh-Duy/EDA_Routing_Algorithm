# Deterministic scenarios

Regenerate only these files with `python3 benchmarks/generate_layouts.py`.
Generation is separate from execution. The original `data/` inputs are never
regenerated by this script. Coordinates and dimensions use `(layer, row, column)`.

| File | Dimensions | Nets | Purpose |
|---|---|---:|---|
| simple_2d | 1 × 3 × 5 | 1 | Open 2D grid, shortest route 4 planar edges |
| obstacles_2d | 1 × 3 × 3 | 1 | Barrier forces a 6-edge planar detour |
| multilayer | 3 × 1 × 1 | 1 | Exactly 2 VIAs, including a VIA into the destination |
| via_sensitive | 2 × 5 × 7 | 1 | 10-edge planar route versus 8-edge route with 2 VIAs |
| congestion | 1 × 7 × 7 | 2 | First route blocks the second; history can move it to a detour |
| impossible | 1 × 1 × 3 | 1 | Obstacle disconnects source and target |
| impossible_overlap | 1 × 3 × 3 | 2 | Both nets must use the single central cell; no disjoint solution |
| stress_seeded | 4 × 40 × 40 | 12 | Random obstacle stress case, 6,400 cells |

The stress generator uses Python `random.Random(20261016)` and independently
marks each cell blocked with probability 0.18 before placing 24 endpoint tokens.
Pin placement overrides obstacles at those coordinates. Endpoint coordinates
are fixed by the generator. There is no selection of seeds based on success.
Generation is deterministic for the documented Python environment; committed
layout bytes and recorded SHA-256 hashes define the actual test instances.

These are synthetic educational layouts, not industrial benchmark circuits.
The suite also runs all six existing layouts, including `chip_layout_hell.txt`.
See `docs/AUDIT.md` for the two documented input repairs.
